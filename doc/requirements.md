# KCS Navi 要件定義

## 1. 機能要件

### 1.1 展示作品・ブースマップ

| ID   | 機能要件                                                                       | 優先度 |
| ---- | ------------------------------------------------------------------------------ | ------ |
| F-01 | ブース全体のマップを表示できる                                                 | Must   |
| F-02 | マップ上に各展示机の位置を表示できる                                           | Must   |
| F-03 | 机を選択すると、その机に対応する展示作品を確認できる                           | Must   |
| F-04 | 展示作品の詳細情報（作品名、説明、制作者、所属班、制作者コメント）を閲覧できる | Must   |
| F-05 | 1つの机に複数の展示作品がある場合、それぞれ閲覧できる                          | Should |
| F-06 | 展示作品を一覧表示できる                                                       | Should |
| F-07 | 作品名・班名・タグなどで、展示作品を絞り込み検索できる                         | Could  |

### 1.2 班紹介

| ID   | 機能要件                               | 優先度 |
| ---- | -------------------------------------- | ------ |
| F-08 | 各班の名前・紹介文を閲覧できる         | Must   |
| F-09 | 各班が制作した展示作品を一覧表示できる | Should |
| F-10 | 各班のメンバーを閲覧できる             | Should |
| F-11 | 各班の写真や活動内容を閲覧できる       | Could  |

### 1.3 来場者数・混雑度管理

| ID   | 機能要件                                                 | 優先度 |
| ---- | -------------------------------------------------------- | ------ |
| F-12 | 来場者が入口のQRコードからチェックインできる             | Must   |
| F-13 | チェックインした日時を保存できる                         | Must   |
| F-14 | 当日のチェックイン数（延べ人数）を集計・表示できる       | Must   |
| F-15 | 日別のチェックイン数を集計・表示できる                   | Must   |
| F-16 | 時間別のチェックイン数を集計・表示できる                 | Must   |
| F-17 | 直近20分間のチェックイン数を推定滞在人数として算出できる | Must   |
| F-18 | 推定混雑率を「推定滞在人数÷定員40人×100%」で算出できる   | Must   |
| F-19 | 推定滞在人数・推定混雑率を推定値と明記して表示できる     | Must   |
| F-20 | 推定混雑率を一定間隔で再計算・表示できる                 | Must   |
| F-21 | 同一利用者による短時間の重複チェックインを抑制できる     | Should |
| F-22 | 日別・時間別チェックイン数の推移をグラフで表示できる     | Should |

### 1.4 リアクション機能

| ID   | 機能要件                                                     | 優先度 |
| ---- | ------------------------------------------------------------ | ------ |
| F-24 | 来場者が展示作品にリアクション（いいね）できる               | Must   |
| F-25 | 展示作品ごとのリアクション数を表示できる                     | Must   |
| F-26 | 複数種類のリアクション（いいね、拍手、笑顔など）を付けられる | Could  |

### 1.5 その他の機能

| ID   | 機能要件                                         | 優先度 |
| ---- | ------------------------------------------------ | ------ |
| F-27 | ハンバーガーメニューから各ページに移動できる     | Must   |
| F-28 | サイト内で現在のページ・画面を識別できる         | Should |
| F-29 | 三田祭の基本情報（開催日時、会場など）を表示する | Should |
| F-30 | ホーム画面への追加などPWAの機能を提供する        | Could  |
| F-31 | 通信エラー時に適切なエラーメッセージを表示できる | Must   |

## 2. 非機能要件

### 2.1 性能・パフォーマンス

| ID    | 非機能要件           | 目標案                                                                           |
| ----- | -------------------- | -------------------------------------------------------------------------------- |
| NF-01 | ページの表示速度     | 主要ページのLCPが2.5秒以内を目標とする                                           |
| NF-02 | APIの応答速度        | 通常負荷で95%以上のリクエストを1秒以内に処理                                     |
| NF-03 | 同時アクセスへの対応 | 仮に100人の同時利用を想定し、負荷試験で検証                                      |
| NF-04 | 混雑度の情報更新     | 直近20分間のチェックイン記録から計算した推定混雑率を、30秒以内を目安に再取得する |
| NF-05 | 画像などの最適化     | 必要に応じて圧縮・遅延読み込みを行う                                             |

### 2.2 可用性・信頼性

| ID    | 非機能要件             | 目標案                                                                       |
| ----- | ---------------------- | ---------------------------------------------------------------------------- |
| NF-06 | 文化祭開催中の安定稼働 | 開催時間中に継続利用できること                                               |
| NF-07 | サーバー障害への対応   | 再起動・復旧手順を用意する                                                   |
| NF-08 | データの永続性         | サーバーやアプリの再起動で記録データが消失しない                             |
| NF-09 | データのバックアップ   | 重要データを定期的にバックアップできる                                       |
| NF-10 | 同時更新の整合性       | 同時チェックインでも記録が欠落せず、チェックイン数を整合的に集計できる       |
| NF-11 | 情報の鮮度             | チェックイン記録の最終更新時刻を保持し、混雑度が推定値であることを判別できる |

### 2.3 セキュリティ

| ID    | 非機能要件               | 目標案                                              |
| ----- | ------------------------ | --------------------------------------------------- |
| NF-12 | HTTPS通信                | 公開環境ではHTTPSを使用する                         |
| NF-13 | 認証・認可               | 管理系APIは適切に認証・権限確認する                 |
| NF-14 | 入力値検証               | 不正な型、範囲外の値、不正なデータを拒否する        |
| NF-15 | 不正リクエスト対策       | チェックイン・リアクションAPIに連続送信対策を設ける |

## 3. 開発スコープ

- 初回リリースは、機能要件の優先度がMustの項目を対象とし、Should・Couldの項目は原則として含めない。ただし、以下で明示した変更は今回の決定を優先する。
- フロントエンドはVueとTypeScriptで実装する。
- アプリケーションにはNuxtを採用し、サーバー処理にはNitro、データベースにはCloudflare D1を使用する。
- 展示マップは疑似3Dで表現する。机は作品詳細を開くボタンとして扱い、その位置と識別子はコード内の固定設定で管理する。地図を編集する機能は設けない。
- 初回リリースでは`desks`テーブルを作成しない。作品テーブルに`desk_key`を持たせ、固定設定の机の識別子と対応づける。これにより、1つの机に複数の作品を紐づけられる構造とする。
- 班と作品の関係は1対多とし、各作品は1つの班に所属する。班と作品は作品テーブルの班IDで紐づける。
- 独立した制作者名の項目は設けず、作品テーブルに制作者コメントを保存する。制作者名を載せる場合は、登録する人がコメント本文に含める。
- マップの机から開く展示詳細はポップアップで表示する。ハンバーガーメニューから遷移するサイト内の画面は、別ページとして表示する。
- 初回リリースでは管理者ページを作成しない。展示作品や班の情報は、開発者がCloudflare D1に直接登録・更新する。
- QRコードには受付用URLを設定する。QRスキャン後は、受付ページをGETし、ページ読み込み時にJavaScriptで登録フォームを自動POSTする。登録完了後は303リダイレクトによりWelcome画面をGETして表示し、ユーザーが操作する確認・登録ボタンは設けない。
- 同一利用者の識別は行わず、チェックイン集計のための利用者IDや識別用Cookieは設けない。
- いいねの本人回数はlocalStorageで作品ごとに管理し、画面上は1作品10回までとする。日次リセットは行わず、保存データの削除・改変による回避は許容する。サーバーは利用者を識別せず、従来のlikesテーブルにいいね1回につき1行記録する。DB構造は変更しない。
- チェックインは重複しない前提とし、再入場も考慮しない。受け付けたチェックインのPOSTリクエスト1件につき来場数を無条件に1増やし、同一利用者による重複チェックインの排除や再入場判定は行わない。
- 混雑状況は、推定混雑率50%未満を「ゆったり」、50%以上80%未満を「やや混雑」、80%以上を「混雑」とする。推定人数・推定混雑率・更新時刻はマップ上部の混雑状況カードにまとめ、しきい値と表示方針の理由を実装コードのコメントに残す。
- 開発環境はDockerを必須とせず、Node.js上のNuxt開発サーバーとWranglerによるローカルD1を使用する。Node.jsとパッケージ管理ツールのバージョンを固定し、Cloudflare環境での動作をWranglerで確認する。
- 日付・時間別集計の区切り、開催時間外の記録の扱い、直近20分の境界条件は実装時に決定する。採用したロジックと判断理由は、実装コードのコメントに残す。
